# 07 · 知识库、技能、表情包与脚本

> ⚠️ **临时版本提示**：本文档由 DeepSeek 根据当前 Miyu 源码逐行整理，属于临时参考版本；正式版文档仍在施工中，内容可能与最新代码存在出入。请以 `miyu -h`、`miyu config`、仓库 README 及源码为准。

这四样是 Miyu 的“可调教”内容：你不用改代码，就能让它掌握新知识、学会新流程、发新表情、调用新脚本。

## 1. 知识库（kb）

### 它是什么

一个带索引的 Markdown 文件库。Miyu 回答 Linux/Arch 问题时，会先搜知识库和网络，两者冲突时优先信知识库（提示词规则）。默认知识库来自本仓库 `kb/` + Shorin Wiki，打包在 `/usr/share/miyu/default-kb/`。

### CLI

```bash
miyu kb add 文件.md
miyu kb add 目录/
miyu kb list
miyu kb search "N卡驱动"
miyu kb find "nvidia"
miyu kb read 文件名 --start 1 --lines 200
miyu kb remove 文件名
miyu kb stats
miyu kb reindex
miyu kb embed reindex --quiet   # 配了 embedding 才有意义
```

也可以直接用自然语言让 AI 操作（有 `upload_text_to_knowledge_base`、`edit_knowledge_base_file` 等工具）。

### 检索与索引

- 默认关键词/短语检索：`search`（内容）和 `find`（文件名）。关键词命中分内容 +90、文件名 +140，再加词项命中/覆盖率和窗口分；语义检索开启且关键词分较弱时才混合语义分。
- 语义检索默认开启（`embedding.enabled` + `plugins.knowledge_base.embedding_enabled`），默认用内置本地模型 `bge-small-zh-v1.5-int8`（需要系统装有 ONNX Runtime，Arch 为 `onnxruntime-cpu`），也可以在 `embedding` 里换成远程 `/embeddings` 接口。`miyu kb embed reindex` 或 `miyu embed reindex` 重建向量索引；写入文件后会自动起子进程补索引。向量按模型打标签，换模型后旧向量作废、增量重建。
- 语义检索只是辅助：运行库缺失、模型目录缺失或远程超时时静默退回关键词，`miyu embed status` 能看到原因。
- 限制：单文件大小、读取行数、snippet 长度、top_k、min_score 等都在插件配置里。
- 用户知识库目录：`~/.miyu/data/kb/`（默认，可改 `plugins.knowledge_base.data_dir`；内部还有 `files/`、`kb_meta.db`、`semantic_index.db`）。

### 默认知识库更新

```bash
miyu update-default-kb
```

- 用 git 更新 Shorin Wiki（clone 时 `--filter=blob:none` 省流量），校验后计算快照哈希，再替换默认文件。
- 状态记录在 state 目录；每 24 小时检查一次远程更新，有更新会提示。
- 打包时缺失 `/usr/share/miyu/default-kb` 不报错，只是默认知识库为空。

## 2. Skills（技能）

Skill 是一份 Markdown 操作手册：模型遇到匹配场景时加载它，按里面的步骤和工具执行。这是给 AI 的“SOP”。

### 内置技能

| 技能 | 文件 | 作用 |
|---|---|---|
| linux-game-compatibility | `src/skills/linux-game-compatibility.md` | 组合 ProtonDB/AreWeAntiCheatYet/CanIPlayOnLinux 判断游戏兼容性 |
| linux-input-method-diagnose | `src/skills/linux-input-method-diagnose.md` | 从原理出发诊断 Linux 输入法问题 |
| skill-creator | `src/skills/skill-creator.md` | 教 AI 如何创建一个好 skill |

### CLI

```bash
miyu skills list
miyu skills show 名字
miyu skills enable 名字
miyu skills disable 名字
miyu skills remove 名字
miyu skills stats
miyu skills prune
```

### 创建流程

1. 对 Miyu 说“帮我创建一个解决 XX 问题的技能”。
2. AI 调 `create_skill` 生成**草稿**，放在 `~/.miyu/state/skill-drafts/`。
3. AI 用 `update_skill` 完善；`list_skill_drafts` 查看草稿。
4. 确认无误后 `publish_skill` 发布到用户技能目录。
5. 用 `load_skill` 测试；不需要就 `delete_skill`。

### 安全与规则

- 技能默认允许在 AI 按技能操作时执行命令；`skills.allow_command_execution=false` 全局禁止技能命令执行。
- 用户技能属于用户资源，`miyu export/import` 会带上。
- 技能优先级：当前人格技能 > 全局用户技能 > 内置技能；同名会遮蔽；目录里放 `.disabled` 文件即可停用。
- 草稿未发布保留 30 天，已发布归档保留 24 小时。
- SKILL.md 的 frontmatter 必填 `name`/`description`；`name` 必须与目录名一致；`allowed-tools` 只是元数据，不授权限。
- 发布是原子操作（新技能绝不覆盖、更新失败自动回滚），全程拒绝 symlink。

## 3. 表情包（memes）

### 存储位置

- 系统内置：`/usr/share/miyu/memes/miyu/`（源码 `src/memes/miyu/`，30+ 张）。
- 用户目录：`~/.miyu/data/memes/`。
- 索引：每个表情库目录一个 `index.json`，包含每条表情的 id、标签、描述、文件等。

### 自动发送

- 聊天时 Miyu 会按概率自主发符合情境的表情；插件配置可调 `auto_send_probability`（默认 0.05）、置信度、冷却、图片尺寸等。
- 自动发送只跟人格库走：新建人格默认没有 Miyu 内置表情，需要把图片路径给 AI 让其 `manage_meme(action=add)`。
- 识图：添加图片时，AI 自动调用多模态模型分析内容并写描述（默认 opencode vision 模型即可，不配也能用）。
- 工具分两个，按**加载成本**分而不是按「像不像一件事」：
  - `use_meme`（`action=search` 找候选 / `show` 发送）——发表情是高频动作，常驻目录，不需要先加载。
  - `manage_meme`（`action=add` / `update` / `delete`）——低频，挂在 `memes` 组里懒加载，平时只占一条 155 字符的精简条目。
- 两个工具在终端和群聊里都有。`manage_meme` 是写工具，但只写人格自己的表情库目录，和 `generate_image` 一样属于平台注册表「全员只读」那条断言的明示例外。
- 识图入库门槛很严：分类置信度必须 100，7 个正向 gate 全过、5 个风险 gate 全不过，才会自动保存。
- QQ 群还有“表情口袋”插件：按概率（默认 2%）自动收集群友图片入表情库；管理员可保存/删除。

## 4. Scripts（脚本）

一个可执行文件就是一个工具：Miyu 从文件开头的注释读工具契约（描述、参数 schema、超时、分组），用 JSON 传参把它跑起来。完整接口说明见 `docs/scripts/README.md`，模型侧的同一份契约在内置技能 `script-creator` 里。

### 目录（同 id 后者覆盖前者）

| 目录 | 说明 |
|---|---|
| `/usr/share/miyu/scripts/personas/default/` | 内置脚本，只有默认人格看得到 |
| `~/.miyu/data/scripts/` | 全局用户脚本 |
| `~/.miyu/data/scripts/personas/<人格>/` | 人格专属脚本，`manage_script` 默认落在这里 |

### 头部即契约

```
#!/usr/bin/env python3
# Display name: 番组日历
# Description: Query the Bangumi airing calendar. Use for "what airs today" questions.
# Timeout: 60
# Group: research
# Parameters:
# {"type": "object", "properties": {"query": {"type": "string", "description": "keyword"}}}
```

`Description` 英文、首句 ≤60 字符；`Parameters` 是 JSON Schema，可多行；`Id` 可覆盖由文件名推出的工具名（`battery-care` → `battery_care`）；`Argv: flags` 让参数额外展开成 `--key=value`。传参默认是 stdin 上的一个 JSON 对象，同一份也在环境变量 `MIYU_ARGS_JSON` 里。

### index.json 是覆盖层

每层目录可有 `index.json`，条目里显式写的字段压住头部、没写的从头部补；`disabled` 名单屏蔽本层及更低层的同名脚本（内置脚本只能这样屏蔽）。内置脚本已全部迁到头部（09-05），不再带 index.json；`manage_script` 只把你显式传的覆盖字段写进 index。

### 内置脚本

| 脚本 | 功能 |
|---|---|
| `bangumi` | Bangumi 放送表、条目搜索与详情 |
| `battery_care` | 笔记本电池信息与充电阈值（改阈值需 sudo） |
| `bilibili_live_stream` | B 站直播间：标题/分区/开播推流码/下播 |
| `crack_search` | 游戏破解状态（crackrelease + isitcracked） |
| `flight_deals` | 机票比价与日期窗口扫描 |
| `goofish_search` | 闲鱼搜索与监控（依赖 playwright/Chromium） |
| `hotel_deals` | 酒店比价与入住日扫描 |
| `procusage` | 进程 CPU/内存占用与排名 |
| `showenv` | 环境变量查看 |
| `xhs_search` | 小红书搜索与正文（需扫码登录） |
| `zhihu_search` | 知乎搜索与回答 |

### 注册与安全

- AI 用 `manage_script`（action=register，`path` 给任意绝对路径）注册：文件被复制进当前人格目录、设可执行位，下一个工具回合即可调用；`action=list` 列出已注册/未注册/禁用；`action=unregister` 屏蔽或删除。
- 直接放进目录的文件只要有 shebang 和 `# Description:` 头部就会被自动检测；缺描述的只出现在 `unregistered` 列表，不会成为工具。目录一变下一回合自动重扫。
- WebUI 控制台有「脚本」面板（09-05）：列出四层里全部脚本工具（所在层、参数、超时、分组、加载方式、argv），点开看描述来源、schema 与文件开头；可禁用/启用/删除，未注册文件可当场补一句描述登记。接口 `/api/dash/scripts/*`，写操作与 `manage_script` 同一套逻辑。
- 脚本默认按需加载（`load_tools` 目录可见），index 里 `always_loaded: true` 可强制常驻。
- 脚本执行受超时（默认 120s，上限 300s）、8 MiB 输出硬上限、20000 字符展示软上限约束；脚本路径必须在脚本目录内。
- QQ 受限平台没有脚本工具。
