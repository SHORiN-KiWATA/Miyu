# 05 · 配置指南

> ⚠️ **临时版本提示**：本文档由 DeepSeek 根据当前 Miyu 源码逐行整理，属于临时参考版本；正式版文档仍在施工中，内容可能与最新代码存在出入。请以 `miyu -h`、`miyu config`、仓库 README 及源码为准。

## 1. 配置在哪里

| 项 | 位置 |
|---|---|
| 主配置 | `~/.miyu/config/config.jsonc`（JSONC，允许注释） |
| 默认人格 | `~/.miyu/data/prompts/system-prompt.md` |
| 开发模式提示词 | `~/.miyu/config/dev-prompt.md`（旧资源布局） |
| 用户身份 | `~/.miyu/data/identities/user-identity.md` |
| 自定义人格 | `~/.miyu/data/prompts/` 下每个 `.md` 一个人格 |
| 技能 | `~/.miyu/data/skills/` |
| 脚本 | `~/.miyu/data/scripts/` |

> 老版本曾使用 XDG 目录（`~/.config/miyu`、`~/.local/share/miyu` 等）。新版启动时会自动迁移到 `~/.miyu`，迁移失败会拒绝启动且**零写入**。设置 `MIYU_HOME` 可整体换位置。

推荐用 TUI 修改：

```bash
miyu config
miyu config validate
miyu config paths
```

主菜单 10 项：供应商/模型、文本模型、多模态模型、Embedding、子代理档位池、插件、自定义提示词、IM 平台、全局设置、保存退出。`j/k` 移动，`Enter` 进入，`q/Esc` 退出；退出时有改动会询问是否保存。

## 2. 供应商与模型

### 核心概念

- **供应商（provider）**：一个 API 端点。内置 11 个模板（含 opencode、DeepSeek、OpenAI、Anthropic、Moonshot、Qwen、GLM、taotoken 等）。
- **默认供应商** `active_provider`：默认是 `opencode`（opencode zen 公共端点）。
- **文本模型池** `active_provider_models`：`None` = 跟随当前供应商的 `default_model`；`Some` = 启用多选池，CLI 可 `miyu models` 切换。
- **多模态模型池**：识图时用；未配置时按“显式 vision provider → 活跃多模态池 → opencode 默认 vision 模型”回退。
- **Embedding**：知识库语义检索可选配置，不配也能关键词检索。

### Provider 字段

| 字段 | 说明 |
|---|---|
| `id` | 唯一标识（配置里大量引用它） |
| `display_name` | 显示名 |
| `base_url` | API 根地址 |
| `protocol` | `auto` / `openai-chat` / `openai-responses` / `anthropic`（内置 Claude Code 条目内部使用 `claude-code`，不在表单下拉里） |
| `api_key` | 支持 `$env:变量名` 和逗号分隔多 key（多 key 自动轮转/冷却） |
| `models` | 模型清单，可写 `context_window`、`temperature`、`modalities`、`cost`、reasoning |
| `default_model` | 默认模型 |
| `timeout_seconds` | 会被 clamp 到 5–30 秒 |
| `extra_body` | 透传 JSON 对象（保留字段会防覆盖） |
| `anthropic_max_tokens` | Anthropic 协议 max_tokens 上限 |

温度覆盖顺序：模型温度 → 供应商温度 → 默认 1.0。上下文窗口：模型配置 → 在线模型缓存 → 默认 168000；多模型激活取**最小值**。

### 协议自动判断（不需要你操心）

- 模型是 gpt-5/o 系列或显式 `openai-responses` → Responses API。
- provider 名/URL 像 Anthropic 或显式 `anthropic` → Messages API（带 `x-api-key` + `anthropic-version: 2023-06-01`）。
- 其他 → Chat Completions。
- DeepSeek 白名单 provider 才回传 `reasoning_content`；taotoken + glm 会传 `enable_thinking`。
- `claude-code` / `antigravity` 永远不会被自动猜到，必须显式配置（见下两节）。

### Claude Code 订阅接入（内置特殊供应商）

把本机已订阅登录的 Claude Code CLI 当供应商用：Miyu 的请求经 `claude -p` 子进程
（stream-json 双向流）出去，走订阅额度，Miyu 不经手任何凭据。

它**不是**你手动添加的 HTTP 供应商：供应商列表里天生就有「Claude Code」这一
项，**默认未启用**。在「供应商和模型」里选中它回车，会打开专用编辑表单——
只有启用总开关、显示名、claude 可执行文件路径、工具桥开关和流空闲看门狗，
没有 base_url/协议/API Key/超时/额外请求体这些对它没有意义的字段。启用开关
是**总开关**：同时决定订阅中转可选与 `claude_code` 委托工具注册。

模型列表预置 CLI 认识的别名 `fable` / `opus` / `sonnet` / `haiku`（默认
sonnet），照常在模型菜单勾选进文本模型池。每个模型有思考档
`low / medium / high / xhigh / max`，映射到 CLI 的 `--effort`，用
`miyu variant` 或模型菜单切换。

要点：

- 未启用时不进任何模型选择器；激活池指到它会得到明确的「供应商未启用」报错。
- 系统提示词（人格/开发提示词）经 `--system-prompt` 整体替换，claude 自带的
  CLI 身份与 CLAUDE.md 不会注入。
- **工具循环在 claude 侧闭环**，工具面由两个四档作用域（`off/dev/normal/all`，
  在专用表单里改）决定：
  - **Claude 原生工具**（Bash/Edit/Read…，默认 `all`）：训练分布内、编码能力
    最强；开启时按表单里的权限模式跑（默认 `bypassPermissions`——无头模式没
    有交互审批，不 bypass 则 Bash 被拒），工作目录是会话工作区；
  - **Miyu 工具经 MCP 桥**（默认 `all`）：经 `miyu mcp-serve` 打回 daemon，
    内层调用照走 guard/超时管线；工具图片/artifact 照常落资产并实时推给
    REPL/WebUI 渲染，ask_question 走既有问答弹窗。两个作用域可叠加；**同时
    开启时自动去重**——与原生重复的 Miyu 工具（read_file/apply_patch/
    run_command/web_search/web_fetch/glob/grep/todowrite）剔除，原生优先；
    **task/job/alarm 保留**：claude 自带的后台与定时活在单次进程里、轮末即
    杀，Miyu 的 task（daemon 后台子代理+完成唤醒跟进）/job（查停）/alarm
    才是这套架构下能跟进的版本，系统提示词里也注入了这条环境事实。
- **会话续传**：同一会话内按 append-only 前缀链匹配自动 `--resume`，每轮只发
  增量；redo/compact/重启后自动整段重放，不损失正确性。不同 Miyu 会话严格
  映射到不同 claude 会话；**清空/删除 Miyu 会话会联动**丢弃映射并删除
  claude 侧的会话转录。
- **平台回合同样可用**：它就是一个普通的供应商/模型，QQ 等平台会话命中时照常
  中转（08-20 起，早期的"仅限本机"门禁已撤销）。订阅限流按 429 处理
  （600s 冷却 + 故障转移）。
- 温度不透传；用量按 Anthropic 口径记账，订阅无按 token 计费，成本列仅供参考。
- 中转相关设置在专用表单里改，落盘于 `plugins.claude_code`：`binary`（空 =
  PATH 上的 claude）、`native_tools`/`miyu_tools` 双作用域、`permission_mode`、
  `idle_timeout_seconds`（注意：原生工具跑长时间无输出的命令会撞看门狗，需要
  的话调大）；另有仅文件可改的 `prefer_subscription`（剥离环境里的
  ANTHROPIC_API_KEY，强制走订阅）与委托工具专用的
  `timeout_seconds`/`max_output_bytes`。

### Antigravity（agy CLI）接入（内置特殊供应商）

把本机已登录的 Google Antigravity CLI（`agy`）当供应商用，形态与 Claude Code
完全同构：请求经 `agy --print= --input-format stream-json` 子进程出去，走 Google
的额度，Miyu 不经手凭据。供应商列表里天生有「Antigravity」（排在 Claude Code
之后），**默认未启用**，回车打开专用表单：启用总开关、显示名、agy 可执行文件、
原生工具/Miyu 工具两个四档作用域、桥工具 eager 开关、流空闲看门狗、
`--print-timeout`。落盘于 `plugins.antigravity`。

模型列表预置 `agy models` 的输出（gemini-3.8-flash-high/medium/low、
gemini-3.1-pro-*、claude-sonnet-4-6、claude-opus-4-6-thinking、gpt-oss-120b-medium，
默认 gemini-3.8-flash-high）；gemini/gpt-oss 的思考档编码在模型名后缀里，只有
claude-* 模型有 `low/medium/high` 三档映射到 `--effort`。

与 Claude Code 线的差异（都是 agy 的形态决定的）：

- **人格不走命令行参数**：agy 没有 `--system-prompt`，Miyu 把系统提示词写成
  全局自定义代理 `~/.gemini/config/agents/miyu/agent.md`（正文整体替换 agy 的
  默认指令，提示词变了才改写），每轮 `--agent miyu` 挂上并校验 init 事件里的
  代理名——没挂上会报错而不是静默跑在 agy 默认提示词上。你在交互式 agy 的
  `/agents` 面板里会看到这一条。
- **原生工具面靠代理文件的 `tools:` 白名单**：`run_command / view_file /
  write_to_file / replace_file_content / find_by_name / grep_search / list_dir /
  read_url_content / search_web`。故意不列 `ask_question`（无头模式下它会被瞬间
  跳过）和 `generate_image`（原生生图的图片进不了 Miyu 的图片通道），这两件只
  留桥版。原生工具一律 `--dangerously-skip-permissions`（不放行则命令被拒且
  agy 仍报成功），工作目录经 `--add-dir` 钉在会话工作区。
- **Miyu 工具桥只能全局注册**：`~/.gemini/config/mcp_config.json` 里的 `miyu`
  条目由 Miyu 维护（只动这一个键），会话身份经 agy 进程环境继承给
  `miyu mcp-serve`；条目里带 `MIYU_MCP_REQUIRE_SESSION=1` 守卫——你自己交互式
  开 agy 时没有会话身份，桥只应答空工具表。桥工具默认 eager 注册（以
  `mcp_miyu_<name>` 原生名直调，schema 进系统提示词，**每轮提示词约 4–5 万
  token**）；关掉 eager 走 agy 的懒加载省 token 但每件工具首次多一步读 schema。
  Gemini 对工具 schema 校验很严，桥会按 Gemini 方言整形（去空 enum、折联合类型、
  剔 additionalProperties 等键），工具自己的 schema 不改。
- **去重名单**：原生开启时从桥上剔除 `run_command / web_search / web_fetch /
  glob / grep`；`todowrite`（agy 没有对应物）、`read`/`edit`（kb:/artifact: 域）、
  `task`/`job`/`alarm`（daemon 常驻后台）保留。
- **续传**：同一 Miyu 会话按前缀链自动 `--conversation <id>` 只发增量。agy 在
  续传目标不存在时**不报错而是静默新开会话**，Miyu 以 init 首行的 id 比对判定并
  立刻重放整段。清空/删除 Miyu 会话（含一次性会话结束）联动删除 agy 侧的
  `conversations/<id>.db*` 与 `brain/<id>/`。
- 思考内容不外露（只有 token 计数）；图片进不了 agy（stdin 只收文本）；没有
  `--autocompact`，Miyu 侧 compact 后照常新会话重放。
- **缓存命中率**：agy 报的 `cache_read_tokens` 经常等于整个 prompt（本轮新输入
  不可能已被缓存，物理上不成立），Miyu 把这种「整段命中」按未报告处理，页脚不
  画 C%；部分命中照实显示。订阅额度不按 token 计费，这个数只影响观感。

### 思考档位（thinking variant）

配置模型时可给每个模型定义思考程度（如关闭/省流/深度）。选择按 `provider_id\tmodel` 持久化在 `state/thinking-variants.json`。CLI `miyu variant` 和 WebUI 模型菜单都可切换。

### 子代理档位池

`subagent_tiers`：cheap / balanced / strong 三档。`task` 工具和深度研究会按档位选模型；未配置回退主模型池。

## 3. 人格与身份

### 系统提示词优先级

`active_persona` 指定的人格文件 → `config.system_prompt` → `custom_system_prompt`。默认人格（`system-prompt.md`）在构建时 XOR 混淆进二进制，用户覆盖后以文件为准。

- **人格文件**放在 prompts 目录，`miyu config → 自定义提示词` 可新建/编辑/删除。
- 人格改名会同步更新 StateStore 里的会话归属；被会话引用的删除会被拒绝。
- **hints/dialogs**：人格可带 `miyu.hint.md` 风格提示和示例对白文件。
- **用户身份**：`user-identity.md`，只有 Owner（终端/WebUI 本地）场景注入，External（QQ 群）不注入。
- **persona reminder**：每 N 轮（默认 3）注入一次蒸馏后的人格提醒；空文件 = 显式停用。
- **Dev 模式**：默认提示词就是一句 “You are a helpful software engineer assistant.”，用户可覆盖 `dev-prompt.md`。

### 平台人格路由

QQ 的每个会话（conversation）可以绑定特定 persona 和模型池；未绑定按全局。普通终端和开发模式永远隔开。

## 4. 插件开关

配置 TUI 的“插件”页可以开关 13 个内置插件。常见默认值：

| 插件 | 默认 | 说明 |

| weather / xuanxue / archlinux / man / hash / package_advisor / moegirl | 开 | 基础日用 |

## 5. 上下文与工具行为

### context（上下文管理）

| 项 | 默认 | 说明 |
|---|---|---|
| `context_window` | 168000 | 默认模型窗口 |
| `tool_output_spill_bytes` | 50000 | 超长工具输出落盘，上下文只留头尾预览 |
| `trim_at_ratio` | 0.8 | 到达窗口 80% 时准备裁剪 |
| `trim_batch_ratio` | 0.15 | 一次释放窗口的 15% |
| `on_overflow` | compact | 溢出策略：compact（压缩）或 pop（弹出旧轮） |
| `compact_force_ratio` | 0.9 | 压缩触发线 |
| `compact_soft_ratio` | 0.5 | 提前提示线 |
| `compact_snip_ratio` | 0.6 | 机械折叠线 |
| `compact_cache_reuse` | true | 压缩时复用实况前缀，保住前缀缓存 |
| `cold_prune_after_minutes` | 1440 | 空闲多久后免费清理旧工具报告 |

### tools

| 项 | 默认 | 说明 |
|---|---|---|
| `enabled` | true | 总开关 |
| `loading_mode` | stub | stub = 懒工具常驻“摘要壳”，缓存最友好；hybrid = 按需加载 |
| `persist_loaded_tools` | true | 会话内记住已加载工具 |
| `max_rounds` | 0 | 单轮最大工具轮数，0 无限 |
| `subagent_concurrency` | 4 | 并行 task 波次 |
| `default_timeout_secs` | 180 | 工具超时；0 关闭 |
| `command_deny` | 默认 5 条 | 命令黑名单子串 |

### cache（高级）

| 项 | 默认 | 说明 |
|---|---|---|
| `keepalive_seconds` | 0 | 每 N 秒重发 1-token 保温 ping，续住 DeepSeek 类热缓存；**按请求次数计费的网关勿开** |
| `keepalive_max_pings` | 20 | 每轮最多 ping 次数 |
| `write_grace_ms` | 0 | 上一请求结束 2.5 秒内的下一请求稍等，躲异步缓存写入窗口 |
| `request_log` | true | 每请求一行 JSONL 绝对 token 数（**不记提示词正文**） |
| `request_log_retention_days` | 14 | 日志保留天数 |

## 6. 显示、通知、语言

- `display.language`：auto/en/zh；`MIYU_LANG` 临时覆盖。
- `display.reasoning`：hidden / summary / full（思考链显示）。
- `display.tool_calls`：hidden / summary / full（工具过程显示）。
- `readable_tool_names`：工具显示成中文可读名。
- `show_token_usage`：回合 token 显示开关。
- `command_output_lines`：命令输出显示行数（默认 10，最大 1000）。
- `repl_replay_turns`：重进 REPL 时回放最近轮次（默认 3，最大 20）。
- `notifications.enabled / on_turn_complete / job_writeback_to_terminal`：桌面通知。

## 7. IM 平台设置概览

详见 [13-QQ与通讯平台](13-QQ与通讯平台.md)。核心项：

## 8. 保存与热重载

- `config.jsonc` 原子写入：临时文件 + persist，不会写坏。
- 保存时自动 normalize：补内置供应商、清理失效模型引用、迁移旧路径、把顶层 memory 复制到 plugins.memory。
- daemon 运行时保存配置会自动请求 reload；忙时重试。
- 人格布局变化会中断正在运行的回合，避免旧上下文继续跑。

## 9. 配置校验规则（常见报错）

- 比例必须满足 `soft ≤ snip ≤ trim ≤ force`，且 force ≥ trim。
- `on_overflow` 只接受 pop / compact。
- 温度 0.0–2.0；provider id 不能重复/空白。
- QQ 端口不能为 0；限流窗口 1–86400 秒。
- 思考档位只接受 minimal/low/medium/high/xhigh。
- 记忆参数：`diary_batch` 2–100，`short_retention` 1–3650 天等。
