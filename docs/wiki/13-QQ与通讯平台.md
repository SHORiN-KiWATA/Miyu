# 13 · QQ 与通讯平台

> ⚠️ **临时版本提示**：本文档由 DeepSeek 根据当前 Miyu 源码逐行整理，属于临时参考版本；正式版文档仍在施工中，内容可能与最新代码存在出入。请以 `miyu -h`、`miyu config`、仓库 README 及源码为准。

Miyu 目前通过 **OneBot v11** 协议接入 QQ（设计上 OneBot 只是第一个平台，核心层是平台无关的）。项目主要针对 **NapCatQQ** 适配。

## 1. 连接方式

### 反向 WebSocket（推荐/默认）

NapCat 作为客户端连 Miyu 开的 WS 服务端：

- 路径：`/ws` 或 `/onebot/v11/ws`
- 默认端口：8300（若 WebUI 改了端口，QQ listener 会跟随实际 web 端口；也可单独配置 `platforms.qq.reverse_ws_port`）
- 鉴权：`Authorization: Bearer <access_token>` 或 `Token <token>`；空 token 只允许本机 loopback 连接
- 推荐传 `X-Self-Id` header，让 Miyu 在收到第一条消息前就知道机器人 QQ 号

### 关于正向 WebSocket

当前 0.4.x 的 OneBot 适配重点实现**反向 WS**（Miyu 做服务端）；NapCat 场景一般用反向 WS 最省事。未来如需 Miyu 主动连接协议端，需要新增正向 WS 客户端实现。

### 连接管理

- 按机器人 QQ 号注册连接；同号新连接会顶掉旧连接（generation 递增）。
- 消息帧最大 16 MiB，每连接同时处理消息上限 32。
- NapCat 自己负责重连；旧连接会清理 pending API 调用，避免重复回复。

### 最简配置

```text
miyu config → IM 平台 → QQ
  enabled           开
  access_token      填与 NapCat 一致的 token
  admin_users       加你的 QQ 号
  private chats → whitelist  加你的 QQ 号（建议）
```

## 1.5 配置模型

QQ 这条线上所有会用模型的地方收在「接入通讯平台 → 腾讯 QQ → 配置模型」一屏（WebUI 在「QQ 平台 → 配置模型」与插件表单里是同名字段）。每一处是一个**池引用**，界面上只显示中文名（英文 locale 下显示英文），不露 `inherit` / `global` / `lite` 这些配置 id；继承一律写成「继承 xx 池」：

| 行 | 配置键 | `inherit` 指向 | 缺省 |
|---|---|---|---|
| 平台文本池 | `platforms.qq.text_models` | 全局文本池（显示「继承全局池」） | inherit |
| 平台多模态池 | `platforms.qq.multimodal_models` | 全局多模态池（不能指向分级档） | inherit |
| 非白名单文本 | `platforms.qq.non_whitelist_text_models` | 平台文本池（显示「继承平台池」） | inherit |
| 回复判定 | `real_context.text_models` | 会话的有效文本池（显示「继承会话池」） | lite |
| 好感度 | `real_context.affection_text_models` | 回复判定 | inherit |
| 入群审批 | `qq_group_join_approval.text_models` | 平台文本池（显示「继承平台池」） | lite |

引用的值：`"inherit"`（上一层）、`"global"`（直接全局池）、`"lite" / "cheap" / "standard" / "flagship"`（分级档，档位空了回退全局池）、或一个显式模型数组（长度 1 就是指定模型，多个就是这一处专属的小池子）。旧配置里的数组照旧解析成显式列表，缺省和 `null` 解析成 `inherit`，不用迁移。删除模型只会从显式列表里剔除（剔空归 inherit），指向池名的引用永远不会断。TUI 里每行 Enter 打开「池单选 + 模型多选」选择框，两区互斥，`d` 清回缺省。

会话专属配置（`conversations[]`）不在这一屏，仍在「私聊/群聊专属配置」里按会话一条条设，语义不变：显式列表优先，否则按「继承平台 / 继承全局」开关。

## 2. 私聊与群聊触发

### 私聊

只要消息里有文本就会触发（图片等纯媒体按平台处理）。非白名单用户受 `allow_non_whitelist` 和限流控制。

### 群聊

满足以下之一才唤醒：

1. @了机器人；
2. 回复了机器人的消息；
3. 命中 `trigger_keywords`（最长关键词优先）。

不满足时 Miyu 不回复（但消息仍会被消息历史等插件记录）。群聊中途追问只在工具执行期可插入；私聊随时可追问。

## 3. 回复方式

- 普通回复：Markdown 会转成纯文本按段发送；`max_reply_chars`（默认 3000）控制切块长度，长回复分多条。
- **长回复转图**：reply_processor 插件默认阈值 300 字符，把 Markdown 渲染成 PNG 图片（主题 paper、宽 960 列、高 1000–5000），发送失败自动回退原文。
- **合并转发**：reply_processor 可切 `forward` 模式，把长回复变成合并转发消息。
- 引用/艾特：real_context 插件决定 quote 和 mention；默认间隔后 @ 对方，保证回复目标清晰。
- 表情包：Miyu 会按概率从人格表情库发送；QQ 群还能自动收集群友图片。
- 图片发送：本地图片转 base64 内联；文件走 `upload_private_file` / `upload_group_file`。

## 4. 权限系统

权限**由代码判定，不靠提示词**。三类：

| 权限 | 对象 | 来源 |
|---|---|---|
| Administrator 管理员 | QQ 用户 | `admin_users` 静态名单，或群内动态授权工具 |
| PrivateWhitelist 私聊白名单 | QQ 用户 | `private_chats.whitelist` 或动态授权 |
| GroupWhitelist 群白名单 | QQ 群 | `group_chats.whitelist` 或动态授权 |

- 管理员免限流、可用非白名单模型、可用宿主工具（发消息/@人）、可执行 `/reset /stop` 等命令。
- 群聊非管理员**永远不能**用宿主工具；私聊需开 `allow_non_admin_host_tools` 且在白名单内。
- 静态名单在配置里，动态授权存 StateStore；工具撤销静态名单会提示“配置名单不可撤销”。
- 动态授权默认全局跨机器人账号生效。

### 限流默认值

| 角色 | 限流 |
|---|---|
| 管理员 | 免限流 |
| 私聊白名单 | 免限流 |
| 私聊游客 | 2 条 / 600 秒 |
| 群白名单 | 30 条 / 60 秒 |
| 群游客 | 2 条 / 600 秒 |

`allow_non_whitelist=false` 可直接拒绝游客。

## 5. 平台斜杠命令

| 命令 | 权限 | 说明 |
|---|---|---|
| `/reset` | 管理员 | 清当前会话；`/reset all` 等参数由执行层处理 |
| `/wipe` | 管理员 | 抹掉上下文；需再回复 `confirm` |
| `/reset-memory` | 管理员 | 清本会话记下的记忆；`confirm` 可选 |
| `/reset-all-memory` | 管理员 | 清当前人格全部记忆；`confirm` 可选 |
| `/stop` | 管理员 | 取消当前回合，历史保留 |
| `/models ...` | 可配置 | 查/切当前会话模型 |
| `/回复处理 status|threshold|mode|reset` | 管理员 | reply_processor 插件 |

命令前缀默认 `/`，可改 1–32 个无空白字符。`/ reset`、`/resetting` 都不是命令。

命令的输出和模型回复走同一套出站插件链，因此 `/models` 这类长清单同样会被
reply_processor 按阈值转成图片或合并转发。只有故障路径上的短通知（限流提示、
会话解析失败、回合异常兜底）绕过插件——它们恰恰在插件可能不可用、或插件本身
就是问题来源时要发出去。

## 6. 群管理插件（默认启用）

| 插件 | 优先级 | 功能 |
|---|---|---|
| access_manager | 300 | 动态授予/撤销管理员、私聊/群白名单，查看名单 |
| message_history | 300 | 记录群/私聊消息历史，供 AI 搜索 |
| group_management | 210 | 禁言/解禁/踢人/踢黑/头衔/管理历史查询 |
| real_context | 200 | 判断该不该回、上下文注入、好感度、审核、回复目标 |
| message_recall | 190 | 撤回消息（自己/群友，需权限与 AI 二次确认） |
| meme_collector | 180 | 概率收集群图片为表情 |
| reply_processor | 100 | 长回复转图/合并转发 |
| qq_scheduled_messages | 0 | 定时发送固定文本（默认关闭；配置会话+每日多时间点，错过不补发，改配置即时生效，详见 docs/plan/2026-08-18-feature-fixes/13-scheduled-messages.md） |

### 群管理工具行为

- **禁言**：单位是**秒**（旧别名曾把 24 小时误解为 24 秒，所以工具返回 `duration_text` 明示换算）。上限 30 天。
- **踢人/踢黑**：`blacklist=true` 踢黑；NapCat 报错时会复查成员是否真的还在。
- **头衔**：长度 ≤18（可配），默认永久。
- 保护：默认禁止对群主/管理员禁言踢人；头衔不保护。
- AI 二次确认：非管理员/非群主触发时，要求模型在同一轮原样重放工具调用确认，防误操作。
- 记录：禁言/踢人/头衔历史、违规者档案；入群审批依赖踢人记录。

### 消息撤回插件

- 撤自己消息直接执行；群内撤别人消息要求机器人是群主/管理员，否则二次确认；私聊不能撤别人。
- 回复目标永远覆盖模型给的 message_id（必须让用户回复目标消息，防撤错）。
- 撤回成功后若这轮还在跑，会取消整个回合。
- NapCat 特殊错误（`retcode=1200 && decode failed`）有专门文案。

### 入群审批插件

- AI 审加入群申请：approve/reject/pending；未配置/插件关闭/AI 失败都保持 pending（fail-closed，不误拒）。
- 超时 60s、最多重试 1 次、并发 8；模型走「配置模型」里的入群审批引用（缺省 lite 档）。
- SnowLuma 协议的 flag 会自动改写，避免系统已处理错误。

### 好友请求

- `friend_requests_require_private_whitelist=true`（默认）时，只自动通过白名单/管理员请求；否则全通过。
- 群邀请只记录日志，保持 pending。

## 7. real_context：Miyu 怎么决定在群里插话

这是 QQ 群聊的核心插件。默认**不是**每条消息都过 LLM 判断，而是：

1. 先看是否 @/回复/关键词直触发；管理员等特权用户可跳过主动判断。
2. 直触发之外，按 `active_judge_probability`（默认 5%）抽样调 judge 模型。
3. judge 从 relevance / willingness / social / timing / continuity 五维打分（0–10），叠加好感度、续聊加成、热度惩罚，过 `reply_threshold`（默认 0.8）才回。
4. 命中违规审核（默认开启，严重度 ≥7.0）会强制触发并附审核提示。
5. 回复后 15 秒内同发送者继续说话有续聊加成；5 秒窗口内的新消息可顶替/继承本轮回复。
6. 连续插话过多会升温“克制度”（reply_restraint），每 heat 扣 0.05 分、阈值 +0.025，3 分钟恢复。

上下文注入：把“此前群聊记录 + 本轮新消息”按 `[时间] 发送者 [msg=id]: 内容` 格式注入，预算 80 KB，水位持久化，旧消息可让 AI 用 `search_real_chat_history` 搜索。

### 好感度

- 默认**关闭**（`affection_enable=false`）。
- 打开后：每个 QQ 用户一份档案，分数 -50~100；普通用户上限 94（进不了“亲近”），白名单可到 100。
- 异步 LLM 更新：12 条历史、置信度 ≥0.8、delta 限制 -10~+2、每天最多 +6/-15。
- 工具只返回挡位/描述/标签/近 3 次变化，**不返回分数**。

## 8. 消息历史

- 自动记录入站/出站/外部机器人消息到 `~/.miyu/data/platforms/onebot/message_history/history.sqlite3`。
- FTS5 trigram 搜索；中文两字词回退 LIKE。
- AI 工具：搜聊天记录、看最近消息、查用户历史、活跃度排行；管理员可跨会话搜/删除。
- 删除需两阶段确认（request → 原样回复短语 → confirm），5 分钟过期。

## 9. 文件与图片

- QQ 文件**不立即下载**；AI 需要读文件时再取。缓存目录 `~/.miyu/cache/platform_files/qq/`，配额 1 GiB / 4096 条。
- 图片解码在 spawn_blocking 里做，带 `image::Limits` 防解压炸弹；单张 10 MiB、共 20 MiB、4 张上限。
- 出站文件 ≤50 MiB；`asset_base_url` 配置了走 URL 上传，否则 base64 内联（≤16 MiB）。

## 10. 安全注意

- 只信 QQ 号，不信昵称：身份映射绑定 canonical identity，冒名者会收到身份冲突提示。
- `user_identification=false` 可隐藏发送者 QQ 号与 @号码。
- 群名/昵称/回复正文都做控制字符清理，防终端注入。
- token 比较用 SHA-256 摘要，防时序/长度探测。
- 所有平台出站附件走 5 分钟租约 URL（`/api/platform-assets/<token>`），最大 50 MiB、最多 128 个租约。
