# 06 · 内置工具与插件

## 工具是什么

Miyu 的工具不是给用户敲的 CLI 命令，而是**给模型看的功能说明书**。你说"帮我查天气"，模型判断需要调用 `get_weather`，Miyu 执行工具并把结果喂回模型，模型再用大白话回答你。

## 真相源与注册机制

- 每个工具的元数据是：`name`、`display_name`（中文显示名）、`description`、参数 JSON Schema、`always_loaded`、`load_policy`（summary/group/hidden）、`groups`、`timeout_seconds`；权限（ReadOnly / Presentation / Writes）由 Rust 代码里的 `.writes()` / `.presentation()` 决定。
- **描述以 `src/tools/descriptions/*.json` 为唯一真相**：JSON 经 `src/tools/tool_descriptions.rs` 的 `include_str!` 宏编译进二进制，注册时（`ToolSpec::apply_built_in_description`）整体覆盖 Rust 代码里的占位描述与参数。唯一例外是 `load_skill`——它的描述是运行时拼的技能目录，但加载策略、分组等元数据仍来自 JSON。
- 三个工具**没有** JSON 文件、用 Rust 内联描述：`job`（后台任务查询/停止）、`query_token_usage`（token 用量）、`load_tools`（懒加载目录本身）。
- 工具分组的摘要与中文名在 `src/tools/descriptions/groups.json`。

## 三套注册表

组装入口都在 `src/tools/mod.rs`：

| 注册表 | 函数 | 场景 | 特点 |
|---|---|---|---|
| Normal | `builtin_registry` | REPL / daemon / WebUI 日常对话 | 完整工具面：网络、文件、命令、知识库、记忆、娱乐、Arch/Linux |
| Dev | `dev_registry` | 开发模式 | 极简：run_command + job + edit + todo + goal + task + web + 独立命名空间的记忆；读检索类不注册（bash 干得更好） |
| 受限平台 | `restricted_platform_registry` | QQ 等不可信会话 | 只读网络/娱乐工具为主；**没有** shell、文件系统、记忆、知识库、MCP、脚本；唯一写例外是 `generate_image`（只写自己的输出目录） |

几条组装规则：

- 插件开关关掉的工具**不注册**（省 token，也省攻击面）。
- 技能（`load_skill`）三套都有；技能创作（`manage_skill`）只在 Normal。
- `ask_question` 按界面能力追加：daemon/WebUI 能弹面板才注册。
- WebUI 会话额外注册 `present_artifact` 与 `share_file`。
- QQ 平台会话在受限注册表之上再内联注册平台工具（见下），记忆工具在管理员（host tools）会话里按发信人重定作用域。

## 懒加载：stub / hybrid / full

`tools.loading_mode` 三档，默认 **stub**：

- **stub**：懒工具全部以"真名 + 一句话摘要 + 宽松参数壳"常驻工具目录，工具数组整会话字节恒定——这是为**前缀缓存命中**做的设计（见 [10-系统设计与架构](10-系统设计与架构.md)）。完整参数合同用 `load_tools` 按需取，结果走对话尾部。
- **hybrid**（别名 lazy）：加载后把完整定义补进工具数组。
- **full**：全部完整定义直接常驻。

`load_policy` 决定单个工具的懒加载行为：`summary` 允许未加载直接调用；`group` 必须先按组加载；`hidden` 不经 `load_tools` 暴露。

### 动态工具

- **MCP**：`mcp.servers` 配置的 stdio server 工具自动注册（N·D）。
  - 工具列表（tools/list）按 server 配置缓存在 daemon 进程里：成功的列表在配置不变时不再重新拉；起不来或超时的 server 记 error 日志、跳过其工具，60 秒后下次重建注册表时再试。多个 server 并行列举，列举预算单独封顶（最多 15 秒 + 5 秒余量），不受 `timeout_seconds`（工具调用超时）影响。
  - daemon 启动最多等 3 秒上下文现算（含 MCP 列举），超过就先就绪、算好再回填，不可达的 MCP server 不会再让 daemon 起不来。
- **脚本**：`~/.miyu/data/scripts/` 里经 `manage_script` 注册的可执行文件成为工具；未注册的脚本文件会出现在 `load_tools` 描述的 `<unregistered_scripts>` 里提示注册。

## 三个存储域与 read 前缀

写入按域分工具（08-21 二次裁定：工具名是最强的能力广告，域内聚合、域间分名）：`edit`=文件系统、`artifact`=Artifact 库、`kb`=知识库，三者都收 `*** Begin Patch / *** End Patch` 补丁。`read` 统一读三域，用前缀选域：

编辑与读取统一成两个工具，用路径前缀选目标存储，**不再各开一套工具**：

| 前缀 | 目标 |
|---|---|
| 裸路径 | 文件系统 |
| `artifact:名字` | 当前会话的 WebUI Artifact 库（`read` 传 `artifact:` 空名 = 列清单） |
| `kb:相对路径` | 知识库（写入走知识库导入/删除，元数据同步） |

一个补丁可含多个 Add/Update/Delete File 段；`edit` 收到带 `artifact:`/`kb:` 前缀的补丁会报错指路到对应工具。旧工具 `apply_patch`（更名为 `edit`）、`read_file`（更名为 `read`）、`write_file`、`edit_file`、`edit_string`、`create_artifact`、`apply_artifact_patch`、`read_artifact`、`upload_text_to_knowledge_base`、`edit_knowledge_base_file`、`read_knowledge_base_file`、`remove_knowledge_base_file`、`claude_code` 均已移除或并入。

## 权限与护栏

- 权限三档 ReadOnly / Presentation / Writes，由代码决定（JSON 里的 `permission` 字段只是给人看的）。受限平台除 `generate_image` 外全部只读。
- 守卫（guard）只拒不放：同一轮里 `review_aur_package` 之后直接 `install_aur_package` 会被拦（必须先经用户确认）；`tools.command_deny` 提供 `run_command` 的子串黑名单。
- 每工具超时可在 JSON 里用 `timeout_seconds` 指定（0=豁免，缺省吃 `tools.default_timeout_secs` 兜底）。
- 删除文件默认走回收站（`trash_path`）；`edit` 写入原子化并渲染 unified diff，Artifact 目录额外防 symlink 逃逸。
