# 2026-09-05 语音 v2:唤醒 + 本地识别 + 听写,零浪费装机

> 目标(用户 09-05 拍板):麦克风常开的唤醒词触发 → 桌面通知「在听」→ 说指令
> → 识别提交 → 执行完成给反馈;**不做 TTS**。同时满足「不用语音的人一分钱
> 不背」与「开着时占用要低、效果要好」。voice 分支(bb697be5 起,08-14~15)
> 只当参考件,不 merge、不照搬。

## 0. 为什么不直接搬 voice 分支

| 分支里的问题 | v2 做法 |
|---|---|
| `voice` 是默认 feature,sherpa 静态库(下载 22MB,链进主二进制 ≈+30MB)人人都背 | 第二个可执行 `miyu-voice`(`required-features = ["voice"]`),主 `miyu` 一字节不碰 sherpa;发布为独立资产 / AUR 拆包 |
| 唤醒对话绑死 TTS:没配 GPT-SoVITS 参考音频就整体停用 | 唤醒对话只依赖识别;反馈=桌面通知 + 提示音 |
| 对话逻辑(StartTurn/分句/打断)住在 worker 里 | worker 只管**音频**(采集/唤醒/识别/提示音);对话、通知、取消全在 daemon 的 voice_bridge |
| STT 默认常驻(+340MB);VAD 安静时也逐帧跑 | STT 用完按闲置时间卸载;VAD 前加能量门 |
| 环境音/媒体声被转成碎片指令 | 最短时长 + 最少字数过滤,SenseVoice 情感/事件标签剔除 |
| 唤醒词灵敏度不可调 | 暴露 boost / threshold |
| 落后 main 302 提交,cli/config/ipc 已拆目录 | 按文件移植,只搬 `src/voice/` 六个纯逻辑文件 |

所有测量数字都是 debug 构建(113MB 安静 / 454MB 常驻 / 2.2% CPU),release
基线见 §5。

## 1. 进程与二进制

```
miyu(主程序,无 sherpa) ──spawn/看护──> miyu-voice(独立二进制,同 lib crate)
      │ voice_bridge                          │ mic(cpal) → 能量门 → VAD → KWS → STT
      │ ·找二进制(同目录→PATH)                 │ 提示音(rodio,内嵌 wav)
      │ ·VoiceAttach 双向信令                  │ 模型缺失自己下载(190MB)
      │ ·语音会话 lane 回合驱动 + 通知           │
      │ ·听写中继(REPL / miyu stt / WebUI)      │
      └ 语音关闭:零线程零内存;二进制缺失:设置页提示安装
```

- Cargo:`voice` feature **默认关**;`[[bin]] miyu-voice` `required-features=["voice"]`;
  lib 暴露 `pub fn voice_worker_main()`。`cargo build` 只出 miyu;
  `cargo build --features voice` 两个都出。
- 定位:`std::env::current_exe()` 同目录下的 `miyu-voice`,找不到再 `PATH`。
- 生命周期:daemon 启动 `voice.enabled` 才拉起;崩溃退避重启;daemon 退出 SIGTERM;
  `ReloadConfig` 时 voice 节变了就重启 worker。worker 侧 attach 断开即退出。

## 2. 信令(VoiceAttach 连接上的 Event 帧)

| 方向 | kind | data | 用途 |
|---|---|---|---|
| w→d | `voice.ready` | `{device}` | 就绪,daemon 记状态 |
| w→d | `voice.wake` | `{}` | 唤醒命中(纯唤醒) |
| w→d | `voice.speech_start` | `{}` | 窗口内开口 0.3s(打断进行中的回合) |
| w→d | `voice.command` | `{text}` | 唤醒态识别出指令 → daemon 起回合 |
| w→d | `voice.utterance` | `{text}` | 听写态识别文本 → 中继给认领者 |
| w→d | `voice.window_closed` | `{}` | 窗口关闭(超时/关窗) |
| w→d | `voice.transcribed` | `{request_id,text}` | 浏览器音频转写结果 |
| w→d | `voice.error` | `{message}` | 致命错误 |
| d→w | `voice.hold` | `{on}` | 回合运行期间冻结窗口计时 |
| d→w | `voice.close_window` | `{}` | end_voice_chat 工具 |
| d→w | `voice.listen` | `{}` | `miyu listen` 快捷键呼叫:不用唤醒词直接进入等待指令 |
| d→w | `voice.dictation` | `{on, source: mic\|stream}` | 听写认领/释放(听写期间唤醒暂停);stream = 音频由 `voice.audio` 推入,麦克风帧丢弃 |
| d→w | `voice.audio` | `{pcm16}` | 浏览器听写的音频块(base64 PCM16 LE 16k 单声道) |
| d→w | `voice.transcribe` | `{request_id,wav_path}` | 浏览器录音 → STT |
| d→w | `voice.cue` | `{name}` | 播 done / error 提示音 |

## 3. 交互链(唤醒路,daemon 侧)

1. `voice.wake` → 通知「未有在听」(worker 已本地播 wake 音)。
2. `voice.command{text}` → 通知「收到:<text>」;`StartTurn` 到「语音会话」lane
   (独立 user lane,WebUI 可翻实录);订阅 run 事件;`voice.hold{on}`。
3. 进行中再收 `voice.speech_start`/`voice.command` → `Cancel` 当前 run(打断)。
4. `run.completed` → 攒 assistant 文本取前 N 字(默认 120)通知「未有:…」+
   `voice.cue{done}`;`run.failed` → 通知 + `voice.cue{error}`;`voice.hold{off}`。
5. 免唤醒追问窗口 `follow_up_seconds`(默认 300)沿用;说「没事了」→ 模型调
   `end_voice_chat` 工具(只在 voice.enabled 时注册)→ `voice.close_window`。

进入上下文的只有识别文本,通知/提示音全在模型视野之外(缓存零影响)。

## 4. 听写(REPL / WebUI / shellhook)

三个入口,一个抽象:**谁有音频谁出音频**。

| 入口 | 音频来源 | 文本去向 |
|---|---|---|
| REPL `/stt` | 本机麦(worker 开听写窗) | 逐句插进编辑框;Esc 停止、回车发送并停止(`dictation_auto_submit` 可改为直接提交)。编辑框有字时打不出 `/stt`,所以停止不走命令 |
| `miyu stt`(终端/shellhook 形态) | 本机麦 | 一句话即提交到终端集成会话,前台流式打印回复 |
| WebUI 麦克风按钮 | 浏览器 `getUserMedia` → 前端重采样成 16k PCM16 → WebSocket `/api/voice/stream` 持续上行 → daemon `voice.audio` 转给 worker,VAD/分句/识别与本机麦同一套 | 识别一句回一句(`{"type":"dictation"}`),逐句填进输入框;输入框上方悬浮电平指示(无文字);静默 10s `ended` 自动结束,再点或 Esc 也能结束。首版的「整段上传 `/api/voice/transcribe`」保留给外部脚本 |

听写窗口固定短窗(10s 静默结束);听写期间唤醒暂停,结束自动恢复。
同一时刻一个认领者。

## 5. 低占用手段与基线

先量(voice 分支 release + 阶段计时补丁,隔离 MIYU_HOME + PipeWire 虚拟声源
注入模型自带 test_wavs;`testkit/voice/measure.py`):

v1 基线(09-05 实测,release,16 核;**与并行编译同跑,个别耗时偏大**):

| 相位 | CPU 均值 | CPU 峰值 | RSS | 备注 |
|---|---|---|---|---|
| 安静(VAD only) | 1.7% | 4% | 高水位 82MB(trim 后 10~50MB) | 每 32ms 一次 VAD |
| 有人声不命中(KWS) | 9.7% | 96% | 同上 | 5s 段:冷 893ms,热 70~160ms |
| 命中 → STT 首次加载 | 7.9% | 120% | 388MB | 加载+首转写 2354ms(加载 ≈2.1s) |
| STT 热转写 | 7.2% | 106% | 282MB 常驻 | 3~5s 音频 160~400ms |
| 限 2 核(模拟弱机) | 待测 | | | |

结论落到设计:Wake 在 KWS 命中即刻上报;STT 默认闲置 60s 卸载;能量门压掉安静
态 VAD。

v2 实测(09-05,`miyu-voice test --timings`,同夹具;完整表见 `docs/voice.md` §九):

| 相位 | v1 全核 | v2 全核 | v2 限 2 核 |
|---|---|---|---|
| 安静 CPU 均值 | 1.7% | **0.4%** | 0.6% |
| 安静 RSS | 高水位 82MB | 79MB | 74MB |
| STT 热转写(3~5s 音频) | 160~400ms | 中位 152ms | 中位 168ms |
| STT 首次加载 | ≈2.1s | 3.2s(并行编译干扰) | 1.4s |
| STT 常驻增量 | +300MB | +300MB(窗口内不卸) | +300MB |

隔离全链 e2e(`testkit/voice/e2e.py`)全部通过。

v2 手段(按收益排序):
1. **能量门**:帧 RMS 低于自适应噪声底 + 余量 → 不进 VAD(安静房间 CPU≈0)。
2. **STT 闲置卸载**:窗口关闭且闲置 `stt_unload_seconds`(默认 60)后 drop
   recognizer;下一次命中重新加载(加载耗时见基线)。
3. 唤醒态地板 = onnxruntime + VAD + KWS 常驻,不再压(换唤醒引擎不值)。
4. `M_ARENA_MAX=2` 沿用到 miyu-voice。
5. (云端 STT 曾做过,09-05 晚用户要求移除,只留本地 SenseVoice。)

弱机:SenseVoiceSmall 是非自回归模型,CPU 只在说话后跑一次(与音频长度线性);
内存是主要代价,靠卸载策略兜;再弱走云端。

## 6. 效果手段

- 过滤:语音段 <0.5s 或识别文本 <2 个有效字(去标点/标签)→ 丢弃不打扰。
- SenseVoice 结果只取 `text`,情感/事件标签走结构字段不入文。
- 唤醒词:`wake_boost`(默认 1.5?按实测)/`wake_threshold`(默认 0.25)写进
  keywords 行 `tokens :boost #threshold`;沿用最长匹配拼音编码。
- sherpa-onnx 1.13.5 → 1.13.7。

## 7. 提示音

内嵌在 miyu-voice 里(24kHz mono 16-bit,各 ≤30KB):`wake`(上行两音「请讲」)、
`heard`(单点)、`done`(下行三音)、`error`(低音小二度)。三套候选音色
(glass / marimba / softpad)由 `testkit/voice/sounds/synth.py` 生成,用户耳选
定稿 **marimba**(09-05),其余两套连同 `sound_theme` 配置项一起删除。
`voice.sounds` 开关,默认开。
