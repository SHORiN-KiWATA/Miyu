# TUI 重写施工单（全屏 ratatui）

2026-09-10。前提只有一条：**它简陋，所以必须轻**。功能面按 testkit/tui-demo 定，不再加；换来的是可量化的
低占用。任何一项预算守不住，就回到现在的 inline REPL，不硬上。

配套：调研与实测在 testkit/tui-demo/README.md（v1–v11 记录）；架构勘察结论见记忆
`miyu-tui-rewrite-research-2026-09-10`。

## 0. 定论

- 路线：全屏（alt screen），程序自己持有历史、选区、悬浮层。inline + 临时全屏的混合路线不做。
- 代价认领：终端原生 scrollback、退出后正文留屏、tmux copy-mode 搜历史，这三样没了。
- 视觉不变：画面逐项沿用现有 REPL（下文 §3），全屏只提供「分页 / 悬浮 / 自绘选区 / 点击」。

## 1. 预算（硬指标，量不到不合并）

基线：现在 REPL 空载 RSS 48.3 MB（载入 21k token 会话，200×60），空闲 0 重绘 0 输出；
demo 单独进程 RSS 3.8 MB、空闲 CPU 0.1%、二进制 +0.3 MB（不含内嵌演示图）。

| 项 | 预算 | 量法 |
|---|---:|---|
| 空载 RSS 增量（对比现 REPL，同会话同尺寸） | ≤ +3 MB | testkit/low-footprint/run.py 同法，smaps_rollup |
| 满 200k 上下文会话的历史留存 | ≤ +2 MB | 原文 + 可见窗口渲染缓存，脚本灌入后量 |
| 空闲 | 0 重绘、0 输出字节、CPU 0% | testkit/tui-demo/cpu_probe.py 的 PTY 字节计数 |
| 流式回合 | 重绘 ≤ 25 Hz；每帧只重算脏条目；输出字节只含变化格子 | 同上 + 帧内分配计数 |
| 按键到画面 | ≤ 16 ms | PTY 时间戳差 |
| 启动重放 1000 条历史 | ≤ 50 ms | 计时 |
| 二进制 | ≤ +1 MB | ls -l |
| 依赖新增 | ratatui（crossterm 后端）一个；不引入 flexbox/布局库 | Cargo.lock 差分 |

## 2. 架构（为守预算而定，不是为了好看）

```
事件源(daemon IPC / 本地 Agent) ─→ 一份分发表 ─→ 条目模型 Vec<Entry>
                                                   │
                        视口(scroll, follow, hover, selection, overlay)
                                                   │
                                      行模型 Row{line, copy, copy_col, click}
                                                   │
                                   ratatui Buffer diff ─→ 终端
```

- **条目模型**存原文（markdown 源、工具头/体、思考摘要/全文、图片 id+尺寸），不存渲染结果。
- **渲染缓存**按条目、按宽度键控：只有可见窗口 ± 一屏的条目保有 `Vec<Row>`；条目变脏（流入、展开/收起）才重算。
  demo 里「每帧重建整份历史」是明确的反面教材。
- **重绘触发**只有三种：输入事件、脏条目、动画（spinner / 任务计时 / 通知），其余时间 `event::poll` 长等。
- **一份事件分发表**：先把 live_turn / one_shot / wake 三份收敛成一份，再接 UI。这是前置工作，不进 UI 预算，但不做不开工。
- 文件规模照 AGENTS.md 红线，单文件 ≤ 800 行：entry / rows / overlay / mouse / kitty 各自成模块。

## 3. 视觉规则（本轮定稿，逐条来自用户裁定）

- 用户消息与输入区：蓝色粗体 `┃`（dev 模式酒红）；上下各一行空竖条。助手正文平铺、无装饰、无边框盒子、无角色名。
- 颜色全部取 render/style.rs 的常量：标题粗体洋红、列表符洋红、行内代码青、粗体=粗体蓝、URL 75 号、图片标签 183 号、思考亮绿 10 号、工具块 dim。
- 底部留一行空。回合中 spinner 行与活动区之间空一行。排队气泡与输入区之间空一行（resume_at 的 queue_gap）。
- **输入框上方出现的任何东西都不带竖条**；与输入区之间空一行；整行清空。命令列表只占 4 行、无按键提示。
- 悬浮块内容缩进到输入框文字列（第 2 列），选中标记 `›` 在第 0 列（洋红粗体），选中行粗体，其余 dim。
- 任务详情沿用工具块词汇：`$ 命令` / `  ↳ 补充` / `  │ 输出` / `  ✓ 完成`；标题行左粗体右 dim 元信息两端对齐；说明文字不进正文。
- 通知：绿色细边框小盒子，绿点 + 粗体文字，居中悬在输入框上方，2.5 s 消失。这是全局唯一允许的边框。
- 不要滚动条，不要「↑N 行 · End 回底」之类的提示。

## 4. 交互规则

- 鼠标由程序接管：拖选反显与复制都不含左侧装饰列；松开即 OSC 52 写剪贴板（不支持时退 wl-copy / xclip）；Shift+拖 留给终端原生。
- 可点击的东西必须有悬停效果（去 dim 提亮）；同一目标的所有行一起亮。列表项悬停即选中、点击即执行。
- 工具块、思考摘要：整块是一个点击目标，点任意处展开/收起；展开时钉住视口。
- 后台任务状态行：点击弹详情覆盖层（命令 / 子代理两种），再点或 Esc 关。
- 输入 `/`：命令列表锚在输入框上方，↑↓ 选、Tab 补全、Enter 执行、Esc 清空。
- 占位符：`[Image N: 名]` / `[粘贴 N: ~L 行]` 洋红，整块跳、整块删；阈值照 placeholder.rs。
- Esc 关任何悬浮层；Ctrl+C 分级（关层 → 清输入 → 中断 → 退出）。

## 5. 从 demo 到产品的缺口（按阶段做）

阶段 0 前置（不进 UI）：三份事件分发表收敛；删 rustyline。
阶段 1 骨架：条目模型 + 行模型 + 渲染缓存 + 事件驱动重绘；接 daemon 一条路径；量 §1 前四项。
阶段 2 输入：多行（Shift+Enter / Ctrl+J）、输入历史、占位符、粘贴、IME 宽字符光标。
阶段 3 渲染：现有 markdown/表格/公式/代码块渲染器改产 `Vec<Row>`；kitty 占位符图片；非 kitty 退化。
阶段 4 悬浮层：命令列表、选择器、任务详情、提问面板（question_tui 改覆盖层）、外部命令让屏。
阶段 5 鼠标：选区/复制、悬停、点击展开、状态行详情。
阶段 6 收尾：resize、SSH 卡顿、键盘协议、config_tui 换同一套组件；全预算复测。

每阶段验收都用现成测具：pyte 抓屏逐格断言（testkit/tui-demo/drive.py 做法）、真 kitty 无头截图
（kitty_probe*.py + kitty-image/run_headless.sh）、PTY 字节/CPU 计数（cpu_probe.py）。
