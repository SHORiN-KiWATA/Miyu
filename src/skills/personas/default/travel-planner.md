# 旅游攻略规划

## 基本原则

- **先搜后答，所有内容标出处。** 景点开放时间、门票价格、交通班次、住宿价格都会变，凭记忆写会误导用户。每条关键信息后附来源链接和查询日期；查不到的明确说"未能核实"。
- **灵活使用可用的信息来源。** 视会话中实际可用的工具选择：网络搜索（始终可用）、知乎搜索、小红书搜索、闲鱼二手市场（找二手门票/装备）、flight-deals、酒店搜索。如果某个专用工具不可用，用网络搜索替代，不要假设工具存在。小红书和知乎内容软广较多，涉及价格和推荐时至少用另一个来源交叉验证。
- **需要购买或预订的东西直接给链接。** 门票、酒店、车票、景点预约，能给官方或正规平台链接就给，省去用户再找一遍。

## 第一步：确定需求

先从用户的消息里提取已知信息，**只问缺失的部分**。用户已经说过的不要再问。用提问工具（如 ask_user_input）询问，每轮不超过 3 个问题，选项式问题比开放式问题更省用户力气。

需要明确的信息：

1. **出发地和目的地** — 未定目的地时见下方"推荐目的地"。
2. **时间** — 出发和返回日期。决定日程长度，也决定季节因素（花期、雪季、雨季、台风）和节假日人流/涨价。
3. **人员构成** — 人数，以及是否有老人、小孩、孕妇、行动不便者。这直接影响每天的步行量、景点选择、住宿位置和是否需要无障碍设施。
4. **偏好** — 名胜古迹 / 自然风光 / 美食 / 网红打卡 / 小众深度 / 休闲放松等。不同偏好下同一个城市的行程完全不同。
5. **出行方式** — 自驾、高铁、飞机；到达后是否租车。
6. **预算** — 总预算或人均预算，以及在住宿、餐饮、交通上的倾向（比如"住得好一点，吃随意"）。

可以合理默认的项目不必追问，但要在攻略开头写明假设（例如："未说明预算，按中档标准规划，人均约 X 元/天"）。

### 可选：推荐目的地

用户没定目的地时，根据时间、人员构成、偏好、预算搜索后推荐 2–3 个，每个说明：当季天气与时令亮点、近期是否有特殊情况（施工、限流、突发事件）、从出发地过去的交通难易与费用。让用户选定后再进入第二步。

## 第二步：获取目的地信息

按第一步的需求有针对性地搜索，至少覆盖以下清单：

- **当季天气与时令**：温度、降雨、日出日落时间（影响每天可用时长）。
- **节假日与人流**：出行日期是否撞上当地假期、大型活动，酒店和门票是否涨价、是否需要提前预约。
- **景点信息**：开放时间、闭馆日（很多博物馆周一闭馆）、门票价格与购买渠道、是否需要实名预约、近期是否临时关闭。
- **交通**：机场/车站到市区的方式与费用；市内公共交通、打车、租车情况；景点之间的实际耗时。
- **住宿**：根据人员构成和预算，找 2–3 个候选区域（考虑离景点近、交通方便、老人小孩不用爬楼等）。
- **餐饮**：符合偏好的餐厅或小吃，注意营业时间和是否需要排队/预约。
- **证件与安全**：跨境需要签证、护照有效期；国内某些区域需要边防证；当地近期治安或自然灾害提示。
- **特殊需求**：有老人小孩时查无障碍设施、母婴室、医院位置；有孕妇时避开高海拔、剧烈项目。

## 第三步：制定详细日程

每天包含：住哪里（区域 + 候选酒店 + 链接）、去哪里（按顺序）、怎么去（交通方式、耗时、费用）、门票怎么买（渠道 + 链接 + 是否需预约）、吃什么（早中晚，含备选）、预计花费。

排完之后自查，这些是攻略最常出错的地方：

- 每天景点之间的移动时间是否算进去了？一天不要超过 3–4 个主要地点，有老人小孩再减。
- 有没有把周一闭馆的地方排在周一？开放时间和到达时间对得上吗？
- 第一天和最后一天扣除了到达/离开的交通时间吗？
- 各项费用加起来是否超预算？超了就调整住宿或减少付费景点。
- 下雨或临时闭馆有没有备选方案？

## 第四步：输出结果

 如用户无特殊要求，默认用 Markdown 输出，按以下结构：

```markdown
# [目的地] X 天行程（[日期]）
## 概览
（人员、预算假设、天气提示、需提前预约的事项）
## 每日行程
### Day 1 [日期]：[主题]
- 住宿：
- 上午 / 下午 / 晚上：（景点 + 交通 + 门票 + 用餐）
- 当日预计花费：
## 预算汇总
（表格：交通 / 住宿 / 门票 / 餐饮 / 其他 / 合计）
## 预订清单
（按时间顺序列出需要提前订的东西及链接）
## 备选方案
（雨天、临时闭馆的替代安排）
## 信息来源
（链接 + 查询日期）
```
